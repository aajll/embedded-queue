# Changelog

All notable changes to this project will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

## [Unreleased]

### Added

- `docs/integration.md`, `docs/api.md` and `docs/design.md`, covering installation and configuration, the API, the ring, the atomic backends and memory ordering, the full policies and critical sections, the footprint, failure behaviour, the MISRA baselines and verification. The README is now a short landing page with a quick start whose output is checked, and a `queue docs examples` test compiles every C block in the README, `CONTRIBUTING.md` and `docs/`.
- A compile-time warning when `QUEUE_OVERWRITE_ON_FULL` is enabled with the default no-op critical-section hooks, on GCC, Clang and the TI compilers. Define `QUEUE_SINGLE_CONTEXT 1` when one execution context performs every queue operation.
- ThreadSanitizer CI job, and tests that force the C11 and volatile backends.
- Added changelog, contributor guide, security policy, standard CI workflow, installed version header, pkg-config metadata, README badge, SPDX headers, and registration for the previously skipped `test_queue_clear` test.

### Changed

- `queue.h` defines `QUEUE_VERSION_MAJOR`, `_MINOR`, `_PATCH`, `QUEUE_VERSION` and a new `QUEUE_VERSION_NUMBER` (`long`, `MAJOR * 10000 + MINOR * 100 + PATCH`), so a copied-in header carries its version. Meson fails to configure when the header and `project(version:)` disagree, and the build needs Meson 0.57 or later.
- CI installs Meson, Ninja and gcovr with `uv` instead of `pip`, checks formatting with the clang-format release pinned in `scripts/format.sh`, runs a MISRA C:2023 analysis with `misch` for each atomic backend against baselines in `analysis/baseline/` that record the existing findings, and builds the library and a `QUEUE_DEFINE` instantiation with TI C2000 CGT 22.6.2 and 25.11.1 under the COFF and EABI object formats, with warnings as errors. The Meson files and tests carry SPDX licence headers.
- The CI coverage gate requires 100% line and branch coverage. Enqueue handles a full queue in a separate path per `QUEUE_OVERWRITE_ON_FULL` mode, so no branch is unreachable in either mode.
- Renamed `LICENCE` to `LICENSE`, standardised copyright text, switched the library target to `static_library`, installed public headers, and aligned Meson defaults with the primitive family baseline.
- Moved the queue logic out of `QUEUE_DEFINE` into type-erased core functions shared by every instantiation; the generated functions are typed wrappers that hold the critical section around each call. `head` and `tail` now live in a `core` member of the generated type, and the critical-section hooks also run for calls rejected with `QUEUE_STATUS_BAD_ARG`.


### Removed

- `queue_version.h`. `queue.h` defines the version macros.

### Fixed

- Unused helpers generated by `QUEUE_DEFINE` no longer raise `#179-D` on the TI C2000 compiler, and a consumer-defined `QUEUE__UNUSED` is respected instead of redefined.
- `queue.h` no longer requires `QUEUE_BARRIER`, which it never used; `queue_conf.h` still defines it as a deprecated alias of `QUEUE_FENCE_SEQ_CST`.
- `head` and `tail` are atomic, with acquire/release ordering between producer and consumer, so the SPSC path is free of data races under ThreadSanitizer. The backend follows the `__atomic`, `<stdatomic.h>`, volatile ladder and can be forced with `QUEUE_USE_*_ATOMICS`; a static assertion rejects targets where `size_t` atomics are not lock-free, which instead select `QUEUE_USE_NO_ATOMICS` with critical-section hooks. The C11 fallback now includes `<stdatomic.h>`.
